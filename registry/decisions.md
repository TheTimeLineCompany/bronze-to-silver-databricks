# Decision log

Record each modelling decision here. One entry per decision. Never delete an entry.
If a decision changes, add a new entry that replaces the old one.

## Template

### D-000X: <short title>
- **Date:** YYYY-MM-DD
- **Status:** proposed | approved | replaced by D-00YY
- **Context:** What problem or question made this decision necessary?
- **Decision:** What did we decide?
- **Consequences:** What changes because of it? Which sources or entities are affected?
- **Approved by:** name (PR link)

---

### D-0001: Silver model is a mix of shared masters and per-source process tables
- **Date:** 2026-10-31
- **Status:** approved
- **Context:** 30 source systems. Many describe the same parts, suppliers, buyers, materials, and locations.
- **Decision:** Master entities are shared (registry/entities.yaml). Process data (pricing runs, container moves, savings tracking) stays in per-source silver tables with foreign keys to the shared masters.
- **Consequences:** Every STTM must map its master keys through registry/key_normalisation.yaml. Changes to shared entities need a change request.
- **Approved by:** project lead

### D-0002: History rule per entity
- **Date:** 2026-10-31
- **Status:** approved
- **Decision:** Masters use SCD Type 2 unless the registry says otherwise. Transaction tables use append or merge. Each STTM table states its `load_pattern` and `scd_type`.

### D-0003: STTM is YAML; Excel is generated
- **Date:** 2026-10-31
- **Status:** approved
- **Decision:** `sources/<id>/04_mapping/sttm.yaml` is the single source of truth. Excel and Mermaid ER files are generated by the `p4-4-sttm-export` skill and are never edited by hand.
